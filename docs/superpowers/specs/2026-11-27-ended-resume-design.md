# 終わったセッションを探して再開する（Ended ビューと PRs からの再開）

## 目的

- 「xxx みたいなセッションってどこだったっけ？」を、`claude --resume` のピッカーで 189 件（直近 14 日）から探さずに済ませたい。
- 「この PR を実装したセッションで経過観察したい」ときに、PR から元のセッションへすぐ戻りたい。

## ゴール / 非ゴール / アンチゴール

- ゴール
  - 直近 31 日の、いま動いていないセッションを一覧にし、キーワードで絞り込める。
  - 見つけたセッションを、ワンクリックで新しい cmux ワークスペースに開ける。開き方は 2 通り。
    - Resume: `claude --resume <id>` でそのまま続きから再開する。
    - Hand off: 同じ cwd で新しいセッションを立て、元のセッションの要点と会話ログのパスを渡す。
  - PRs ビューの、PR を開いたときのセッション一覧からも同じ 2 つで開ける。
  - 各セッションに文脈の大きさ（例: 185k）を出し、Resume と Hand off のどちらにするかをその場で決められる。
- 非ゴール
  - Claude に自然文で探させる検索（会話で「B 案」と呼んだもの）。キーワードで見つからないことが多いと分かってから足す。
  - 31 日より前のセッション。`lib/analytics.mjs` の保持期間に合わせる。
  - 会話の全文（Claude の返答やツール結果）の検索。検索するのは人の依頼文まで。
  - Live の「12 時間以上放置」レーンからの再開。
- アンチゴール
  - 動いているセッションを二重に resume すること。同じ jsonl に 2 つのプロセスが書き込む。
  - 会話ログ由来の文字列（タイトル・依頼文）がシェルのコマンドとして解釈されること。
  - Hand off で立ち上げたセッションが、頼まれる前に会話ログを全部読みに行くこと。Hand off を選ぶ理由（トークンを抑える）がなくなる。

## 背景: resume のトークンコスト

会話の中で、時間が経ったセッションを resume するのは割高かを調べた。

- プロンプトキャッシュは最後の利用から最大 1 時間で切れる。切れた後の resume は、最初の 1 ターンで履歴全体をキャッシュに書き直す。
- 直近 14 日の 179 セッションで測った文脈の大きさ（中央値）は、新規セッションの 1 ターン目が約 7 万トークン、終了時点が約 18.5 万トークン（上位 25% で 26 万、上位 10% で 47 万）。
- `lib/analytics.mjs` の重み（入力 1、キャッシュ書き込み 1 時間 2、キャッシュ読み 0.1）で比べると、resume は最初の 1 ターンで約 23 万ぶん多くかかり、その後も毎ターン約 1.2 万ぶん多い。
- 作業途中で経緯が要るなら resume、マージ後の経過観察のように要点だけでよいなら Hand off、と使い分ける。このため両方のボタンを置き、文脈の大きさを見せる。

## 検討した作り方

- A. キーワード検索。タイトル・すべての依頼文・リポジトリ・ブランチ・紐づく PR を対象にする。（採用）
  - 既存の会話ログ走査（`lib/analytics.mjs`）に依頼文とブランチの保持を足すだけで作れる。即時に絞り込め、コストもかからない。
  - 言い換えには弱い。
- B. A に「Claude に探してもらう」を足す。自然文を `claude -p` に渡し、セッションの索引から候補を順位付きで返させる。
  - 言い換えに強いが、1 回十数秒とトークン代がかかり、作る量はおよそ倍になる。A の上に後から足せる。
- C. ダッシュボードには作らず、ログを grep するスキルにする。
  - 手軽だが、探すたびにセッションを 1 つ立ち上げることになり、一覧で見比べられない。

ユーザーは A を選び、あわせて Hand off ボタンと文脈の大きさの表示を付けることにした（私の提案を採用）。

## 決まったこと

### データ（`lib/analytics.mjs`）

既存の走査（31 日分、差分読み）が持つファイル状態に、次を足す。本体ファイル（`kind === 'main'`）だけでよい。

- `startCwd`: 最初に見えた cwd（サイドチェーンは除く）。会話ログが置かれる `~/.claude/projects/<dir>` はこの cwd で決まる。既存の `cwd` は「最後に見えた cwd」のまま残す。
  - 直近 31 日の 327 件のうち 55 件で両者が違った（45 件は途中で `.claude/worktrees/<name>` に移ったもの）。30 件は最後の cwd がもう無く、始めた cwd は残っていた。
- `branch`: 最後に見えた `gitBranch`（サイドチェーンは除く）。
- `promptTexts`: 人の依頼文（`humanPromptText` が返すもの）の配列。1 件 500 文字で切る。
  - `prune` で時刻とともに消すのではなく、セッションが走査対象に残る限り持つ（ファイル単位で 31 日の期限がかかる）。
  - 1 セッションあたりの上限を設け（例: 直近 200 件）、超えたら古いものから捨てる。
- `firstPrompt` / `lastPrompt` / `lastReply`: 一覧の表示用。`lastReply` は Claude の最後のテキスト返答（`lib/transcript.mjs` の `assistantText` 相当）。それぞれ 300 文字程度で切る。
- `contextTokens`: 最後の本体アシスタントメッセージの `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`。

### 一覧と検索（`GET /api/ended?q=`）

- 対象は、本体ファイルのうち次をすべて満たすもの。
  - 人の依頼が 1 件以上ある。
  - いま動いていない。`collector` の最新スナップショットにある sessionId を除く。
- 並びは最終活動時刻（`lastTs`）の新しい順。
- 検索はサーバー側で行う（依頼文の全文をブラウザに送らないため。私の判断）。
  - `q` を空白で区切り、すべての語を含むものを残す（AND、大文字小文字を区別しない）。
  - 対象の文字列は、タイトル、依頼文すべて、リポジトリ名、worktree 名、ブランチ、cwd、紐づく PR の URL・`#番号`・タイトル。
  - PR のタイトルは `lib/github.mjs` のキャッシュ（`details`）にあるときだけ使う。検索のために GitHub へ取りに行かない。
  - `#1234` と PR の URL は、そのまま上の文字列への部分一致で拾える。
- 返す件数は最大 100 件。`q` が空なら新しい順に 100 件。
- 各行に返すもの: `id`、`title`、`repo`、`worktree`、`branch`、`cwd`、`lastActivityAt`、`firstPrompt`、`lastPrompt`、`lastReply`、`contextTokens`、`prs`（url・番号・あればタイトルと状態）、`match`（依頼文に当たったとき、その依頼文の該当箇所の前後を切り出したもの）、`resumable`、`handoffCwd`。

### Ended ビュー（`public/`）

- ナビの 4 つ目に「Ended」（`#ended`）を足す。macOS アプリの View メニューにも足し、`⌘4` で開けるようにする（`macos/ChanToYare.swift` の配列に 1 件足す）。
- 上部に検索欄。打つたびに少し待って（150ms 程度）`/api/ended?q=` を引き直す。
- 各行の表示
  - タイトル、リポジトリ・worktree・ブランチ、最終活動時刻（相対表記）、紐づく PR（`#番号` と状態）、文脈の大きさ（`185k`）。
  - 最初の依頼と最後の依頼。検索語が依頼文に当たったときは、当たった依頼文の該当箇所も出す。
  - ボタン: Resume / Hand off。
- 立ち上げ先の cwd（私の判断）
  - Resume は `startCwd` で立ち上げる。会話ログはそのプロジェクトフォルダにあり、別の場所からの `--resume <id>` で見つかるかは確かめていないため。途中で worktree に移ったセッションも、ログの場所から確実に再開できる方を取る。
  - Hand off は、最後の `cwd` が残っていればそこ（作業していた worktree）で、なければ `startCwd` で立ち上げる。
- 一覧には `resumable`（`startCwd` が残っている）と `handoffCwd`（Hand off の立ち上げ先。どちらも無ければ null）を返す。Resume や Hand off ができない行は、そのボタンを無効にして理由を出す。

### PRs ビュー

- PR の行を開いたときのセッション一覧（`public/prs.js` の Sessions）の各行に、Resume / Hand off を足す。文脈の大きさも出す。
- そのセッションがいま動いている場合は、2 つの代わりに既存の Open（`/api/focus`）を出す。サーバーは `/api/prs` の各セッションに `running` と `contextTokens` を足して返す。

### 再開（`POST /api/resume`）

- body は `{ sessionId }` だけ。cwd などはサーバーが analytics のファイル状態から引く。ブラウザから渡された値は使わない。
- 断る場合（409 と理由）
  - `session-running`: いま動いている（`collector` の生きているレコードに同じ sessionId がある）。二重 resume を防ぐ。
    - `claude --resume <id>` で立ち上げたプロセスは、`~/.claude/sessions/<pid>.json` に元と同じ sessionId で登録される（2026-11-27 に、稼働中の `--resume` 付きプロセス 5 件で確認）。
    - 立ち上げてからレコードが書かれるまでの間に 2 回押されても二重にならないよう、サーバーは直近に立ち上げた sessionId を 30 秒ほど覚えておき、その間も `session-running` で断る。
  - `session-not-found`: 31 日の走査対象にない。
  - `cwd-missing`: `startCwd` がもう無い。
  - `session-running` の判定は、interactive に限らず生きているプロセスすべてで行う。
- 立ち上げ: `cmux new-workspace --name <タイトル> --cwd <startCwd> --command ' claude --resume <sessionId>'`。
  - sessionId は UUID の正規表現で検査済みのものだけを使う。タイトルは制御文字を除いて 40 文字程度で切る（`execFile` の引数なのでシェルは通らない）。
  - 先頭の空白は `lib/improve.mjs` と同じ理由（`~/.zsh/cmux-claude-resume.zsh` のカウントダウンが最初の 1 キーをキャンセルとして読む）。同じ cwd にこのセッションのマーカーが残っていることが多いので、ここは必ず要る。

### 引き継ぎ（`POST /api/handoff`）

- body は `{ sessionId }` だけ。立ち上げ先は `handoffCwd`。断るのは `session-not-found` と、`handoffCwd` が null のとき（`cwd-missing`）。動いているセッションからの Hand off は許す。
- `lib/improve.mjs` と同じ方式で立ち上げる。依頼文をサーバーがファイル（`~/.cache/cc-dashboard/handoff/<ランダム名>.md`）に書き、コマンドは ` claude "$(cat '<パス>')"` だけにする。
- 依頼文の中身
  - 前のセッションからの引き継ぎであること。
  - 会話ログ由来の値（タイトル、cwd、ブランチ、PR の URL、最初と最後の依頼、最後の返答の抜粋、会話ログのパス）。改善要望と同じく、1 行のデータとして埋め込み、指示として扱わないよう書く（`contextValue` を使う）。
  - 進め方: 引き継ぎ内容を短く確認したら、ユーザーの指示を待つ。会話ログは、指示に必要な部分だけを読む。全文を最初に読まない。
- ワークスペース名は「引き継ぎ: <タイトル>」程度。

### セキュリティ

- `/api/resume` と `/api/handoff` は `POST_ROUTES` に加え、既存の書き込み系と同じ検査（同一オリジン、`X-CC-Dashboard: 1`、JSON のみ、トークン）をかける。
- `/api/ended` は他の GET API と同じくトークン必須。
- HACKING.md の API 一覧・「Chan to Yare が書き込むのは」の記述・Security 節を更新する。README の Usage の表に Ended を足す。

### テスト

- `node:test` で次を確かめる。
  - 検索の絞り込み（AND、大文字小文字、PR 番号、依頼文への一致と `match` の切り出し）。
  - 動いているセッションが一覧から外れること。
  - resume のコマンド文字列の組み立てと、不正な sessionId を断ること。
  - `/api/resume` が動いているセッションを 409 で断ること。
  - 引き継ぎの依頼文で、会話ログ由来の値が改行を含まない 1 行になること。

## 実装する人に任せること

- 一覧・ボタン・検索欄の見た目の細部。既存の Live の行や PRs の行の作りに合わせる。
- 検索を `lib/` のどこに置くか（`lib/ended.mjs` を新しく作る、など）。
- 依頼文の前置きの正確な文面。
- 一時ファイルを消すタイミング（`lib/improve.mjs` と同じでよい）。
- `promptTexts` の上限件数と切り詰めの長さの細かい値。
- `demo/fixtures.mjs` に Ended のダミーデータを足すかどうか（README のスクリーンショットを撮り直すときに要る）。
